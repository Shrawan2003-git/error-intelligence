# Project audit — 12 October 2026

This is a source and local-test audit of the personal Error Intelligence project. It did not use Docker Desktop, company data, a paid API call, or a public staging host. Severity describes the effect **if the affected feature is enabled**; the no-cost local demo keeps provider workers off.

## Verified today

- Docker-free backend verification passed: formatting/build, 18 unit tests, 19 PostgreSQL integration tests, seven Flyway migrations, isolated backup/restore and outage checks, and a 120-request/8-client synthetic load check (P95 16 ms in this run). Earlier runs show host-sensitive latency, so this is not a production capacity result.
- Frontend formatting, lint, 10 unit/component tests, production build, and four desktop/mobile Playwright checks passed in the local demo workflow.
- The local staging demo used isolated project PostgreSQL/Redis data and synthetic events. Provider workers were disabled; no live OpenAI result was verified.
- Git has no commits or remote yet. Ignored local credentials, build outputs, and dependency folders are excluded from the candidate repository files. This is a local review, not a remote CI or deployment result.

## Findings, in priority order

1. **High when embeddings are enabled — repeat ingestion requeues completed embedding jobs.** `IncidentService.group` enqueues an incident embedding for every new event in the fingerprint group. `EmbeddingJobQueue.enqueue` updates a conflicting job to `QUEUED` and resets its attempt count regardless of whether it was `SUCCEEDED` or `RUNNING`. A busy incident can therefore trigger repeated provider calls; a concurrent ingest can also change a running job's status before the worker completes it. The daily AI cap applies to diagnostic analyses, not these embeddings or the synchronous similarity endpoint. Fix by enqueuing only when the source actually needs a new vector, preserving in-flight jobs, and adding a bounded embedding/search budget. Add a real PostgreSQL regression test for repeated events and a concurrent worker claim. Evidence: `back-end/src/main/java/dev/errorintelligence/incidents/IncidentService.java:72`, `back-end/src/main/java/dev/errorintelligence/similarity/EmbeddingJobQueue.java:114`, `back-end/src/main/java/dev/errorintelligence/ai/AiAnalysisService.java:61`.

2. **Medium if raw-event retention is enabled — cleanup can permanently lag.** The scheduled job runs hourly and purges at most 500 expired rows per pass. More than 500 events becoming eligible per hour will grow the expired backlog. The selection sorts globally by `occurred_at`, while the migration indexes start with organization/project, so larger datasets may make each batch slower. Set a policy, add an appropriate expiry index, drain bounded batches with a time budget, expose backlog age/count, and test enabled retention with real PostgreSQL and linked occurrence/fingerprint rows. The current unit test covers only the disabled (`0` days) branch. Evidence: `back-end/src/main/java/dev/errorintelligence/operations/EventRetentionJob.java:35`, `back-end/src/main/java/dev/errorintelligence/operations/EventRetentionJob.java:47`, `back-end/src/main/resources/db/migration/V3__secure_ingestion.sql:25`, `back-end/src/test/java/dev/errorintelligence/operations/EventRetentionJobTest.java:12`.

3. **Medium user-experience gap — authenticated frontend calls have no client timeout.** The public readiness request has an eight-second abort signal, but `secureRequest` and its CSRF request do not. A stalled network call can leave actions waiting without a controlled failure message. Apply a suitable timeout/abort signal to both, preserve the existing refresh retry behavior, and test a hanging request. Evidence: `front-end/src/api/client.ts:11`, `front-end/src/api/client.ts:200`, `front-end/src/api/client.ts:206`.

4. **Low documentation/metadata mismatch — API still reports the Phase 6 label.** The README says the Phase 8 architecture decision is complete, but `/api/v1/system` reads `app.phase: ANALYTICS_AND_OPERATIONS`. Update the runtime label or remove phase from product-facing metadata so it reflects the current state. Evidence: `README.md:11`, `back-end/src/main/resources/application.yml:80`, `back-end/src/main/java/dev/errorintelligence/common/system/SystemController.java:16`.

5. **Verification gap — important live paths are still unproven.** Browser interaction tests use mocked APIs for registration, incidents, similarity, and AI. Backend tests use stubbed model providers. The local staging capture proves real registration, ingestion, grouping, analytics, and resolution, but it is not an automated live browser acceptance test and does not prove paid-provider behavior. Add one synthetic end-to-end browser flow against local staging and keep provider contract tests stubbed for a no-cost baseline. A live AI smoke check is optional and should run only with an explicit budget. Evidence: `front-end/e2e/identity.spec.ts:1`, `docs/portfolio-demo.md`, `docs/phase-5-verification.md`.

## Remaining work

- **Before calling the code release-ready:** fix and regression-test the embedding requeue/cost behavior; finish the retention path if retention is an advertised feature; add deterministic timeout behavior for authenticated UI actions. Run the full Docker-free suite again after changes.
- **For a no-cost CV repository:** make an initial Git commit, create/push to a personal repository, and check the real CI result. The CI workflow exists but has never run remotely. Keep the local screenshots labeled synthetic and describe load results as local, short-run measurements. No public hosting is required to present the project honestly.
- **For the blueprint's Phase 7 production staging gate:** obtain an independent host and verify HTTPS, private PostgreSQL/Redis, secret injection, off-machine encrypted backups and restore, external alerts, dependency advisories, representative load, and deployment rollback. This gate remains open by design under the current zero-spend constraint; see `phase-7-staging-checklist.md`. Phase 8's scale decision is already documented, and Kafka/partitioning are intentionally deferred until evidence warrants them.
